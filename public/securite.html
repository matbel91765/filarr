Comment Filarr Web protège vos données

Cette page dit exactement ce que l'application web garantit — et ce qu'elle ne peut pas garantir. Pas de superlatifs : le modèle de menace, tel qu'il est.

Ce qui est vrai partout

Vos fichiers et vos notes sont chiffrés (AES-256-GCM) avec une clé dérivée de votre mot de passe, avant de quitter votre appareil. Nos serveurs ne stockent et ne transportent que du chiffré : nous ne pouvons ni lire vos contenus, ni les déchiffrer pour un tiers, ni les récupérer si vous perdez à la fois votre mot de passe et votre phrase de récupération.

Deux clients, deux niveaux de confiance

Application de bureauApplication web
Le code que vous exécutez Installé une fois, inspectable, mis à jour explicitement Servi par nos serveurs à chaque chargement
Clé au repos Scellée dans le trousseau du système (safeStorage) Rien par défaut ; en option, scellée sous une clé de session non-extractible du navigateur (14 jours)
Conséquence honnête Zero-knowledge vérifiable : même nos serveurs compromis ne peuvent pas lire vos fichiers Chiffré dans votre navigateur : un serveur compromis ne peut pas lire vos données stockées, mais pourrait servir un code modifié à une session future. C'est la limite structurelle de toute application web — la nôtre comme celle de nos pairs.

En clair : l'application web offre le chiffrement de bout en bout avec le confort du navigateur ; l'application de bureau offre en plus un socle d'exécution que nous ne pouvons pas altérer après coup. Pour la posture maximale, utilisez le bureau au quotidien et le web comme accès d'appoint.

Ce que l'application web fait pour réduire ce risque

  • Content-Security-Policy stricte : aucun script tiers, aucun CDN, aucune origine externe — polices et code servis exclusivement par app.filarr.com, API épinglée sur api.filarr.com.
  • Aucune clé en clair au repos : la clé de chiffrement vit en mémoire de session ; l'option « Rester déverrouillé » la scelle sous une clé non-extractible gérée par le navigateur — le vol du stockage local ne suffit pas à l'obtenir.
  • Votre mot de passe n'est jamais envoyé pour le déchiffrement : la clé est dérivée localement (PBKDF2-SHA-512, 600 000 itérations).
  • Deux relais serveur, deux accords SÉPARÉS, chacun refusé par défaut et chacun avec son interrupteur dans Paramètres → Confidentialité → Sécurité. Accepter l'un n'active jamais l'autre.
    • Aperçus de liens (remplissage ⚡ depuis un lien, titres de liens collés, aperçus de favoris) : seule l'URL de la page transite.
    • Recherches de sources (bouton ⚡ des bases inline quand une source livres/animes/séries/films est choisie) : seuls les quelques mots cherchés transitent, plus votre clé TMDB si vous en avez configuré une.
    Dans les deux cas le contenu de vos notes ne transite jamais, et rien de ce qui passe par ces relais n'est journalisé ni conservé.
  • Session révoquée au moindre doute : déconnexion = clé et session purgées.

Ce que nous ne promettons pas

Nous ne promettons pas qu'une application web égale un client installé — c'est faux chez tout le monde. Nous ne promettons pas de récupérer vos données sans vos secrets — c'est la contrepartie du chiffrement réel. Et nous ne promettons jamais « zero-knowledge » pour le web sans cette page à côté.
